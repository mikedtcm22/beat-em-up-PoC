# WEAPONS: judgement calls

Each is decision / alternative not taken / why. The contract is in `docs/ARCHITECTURE.md` "The catalog, the second weapon and the glint (WEAPONS)".

1. **The def and the scene never refer to each other: `Weapon.def_id`, `WeaponCatalog`.** `WeaponDef.scene` points at the weapon scene (the pinned contract) and the scene names its def by an id export, resolved through the catalog. / Not `Weapon.def: WeaponDef` as an export set in the scene: `pipe.tscn` -> `pipe.tres` -> `pipe.tscn` is a cyclic resource load, which Godot loads badly. / The id costs one export and a lazy getter; an unknown id falls back to the pipe's def so a bare `Weapon.new()` (the M1-M5 tests) still works.
2. **The move set is a `MoveSet` resource on the def and the player registers it under the def's id at pick-up** (`_sets[def.id]`), and `MOVE_SETS` loses its `weapon` entry. / Not a second constant per weapon in `player.gd`, and not a set key string on the def. / Any later weapon is a def and a set file with no player change. `WEAPON_THROW_PATH` stays as a constant because `test_ko_blink.gd` loads the pipe's throw through it.
3. **The chain's swings are their own move ids (`chain_swing_1/2/3`, `chain_throw`), not the pipe's ids with another hitbox.** / Not `pipe_swing_*` with per-weapon data swapped in: the tests, the move-data table, the clip hashes, the Thug's recipes and `hit.move.id` all key on the pipe's ids. / Own ids keep every M1-M5 assertion as it was, let each move carry its own `impact_sfx`, frames and sphere, and the pose table maps both to the same recipes (one `match` arm each), so the swing arcs, the head-meeting and the first-person view tests hold; I added the chain's rows to those tests' loops rather than loosening any.
4. **The chain's reach and timing (D5: "medium reach", the padlock lands last).** Lashes 1 and 2: startup 6 (a whip starts quicker than the pipe's 7), sphere r0.2 moved +0.06 m toward the hand; the finisher: startup 10, active 4, recovery 22, sphere r0.22 moved -0.10 m past the tip. / Not a longer chain (offset out to -0.2 m: the first-person strike envelope, the tip at or below 1.7 m and the pipe's z limit, is only proven for the pipe's tip) and not identical timing. / The damage, tiers, reactions, 3-hit chain and guard drain are the spec's and the pipe's (10, LIGHT/HEAVY/FINISHER, 1.5x), so only feel differs, and every number is a line in `gen_moves.gd` (`CHAIN_*`).
5. **The Thug's three swings take `impact_sfx = pipe` too.** / Not left empty (the tier's hit stack alone). / AUDIO's pools `weapon_pipe_hit` and `weapon_bike_chain_hit` are the weapon's sound, and the Thug swings the same pipe at the player; a pipe that clangs for the player and thuds for the Thug would read as two weapons.
6. **The glint is a camera-facing quad with an additive shader and an angular floor, drawn in the vertex stage; the tunables are pushed from `WeaponGlint`.** / Not a `Sprite3D` or a `StandardMaterial3D` billboard with `fixed_size` (one fixed size cannot be both a near sparkle and a floor angle), and not a pass through `LookPost` (the glint would need the screen-space edge pass's depth). / At the default 1.6 degrees and 0.35 m it is 0.35 m wide to 12.5 m (2.0 degrees at 10 m) and grows with distance after that, so it never shrinks away; additive, so it only adds light and cannot read as a red; a warm white, not the retired amber. It floats `weapon_glint_height_m` (0.45) above the weapon, so a low curb or crate edge at the weapon does not hide it from eye height.
7. **`weapon_floor_amber` (Debug) is the whole M5 look: the amber colour, the thick radius, the art tint, and no glint.** / Not the amber and the glint together (the A/B would not show what the glint alone does). / The inventory's tints read `Tuning.data.weapon_floor_amber`; the default is off, so the amber `tints` fall to 0.
8. **The two M5 amber tests are kept on the amber path with the switch turned on, and a twin on the default path asserts the glint.** `test_level_kit.gd` `test_a_weapon_lying_on_the_floor_is_drawn_in_the_floor_contrast_colour...` and `test_m4_contracts.gd` `test_the_pipe_takes_its_material_and_overlay_from_toon_materials`: old assertions verbatim, with `Tuning.set_value(&"weapon_floor_amber", true)` first; new -> `test_a_weapon_lying_on_the_floor_shows_the_glint_and_keeps_its_own_colour_by_default` and, in the m4 test, the same weapon with the switch off (its own colour, the glint shows). / Not deleting them. / They still pin the A/B switch.
9. **The proxy cylinder stays (hidden) when `art_scene` is set.** / Not removing it as PROPS invited. / Removing it breaks the amber path (`test_level_kit`'s `_albedo()` reads the last child as the cylinder) and the amber path is the Debug A/B; the inventory skips a hidden cylinder, so `cylinder_weapons` is 0 with it.
10. **`ChainSim` steps in world space from `_process` by `delta x TimeController.scale_for(holder)`; it snaps on a jump instead of detecting a holder change.** / Not Jolt joints (the plan: they would push the capsule), not a physics-step sim (the render rate would show the 60 Hz stepping on the whole chain), not an explicit reset hook on attach/throw/drop. / A jump over `weapon_chain_snap_m` (0.6 m in a step; a thrown weapon moves 0.27 m a step) catches a pick-up's reparent, a pickup spot's placement and a teleport with one rule and no coupling to `Weapon`.
11. **The links are drawn by a `MultiMesh` of the art's own `Link` mesh, turned so its long side (Z in the GLB: PROPS built it flat in XZ) lies along the chain.** / Not the straight `StaticArt.repeat_*` stack (links laid flat like rings along Y). / The sim replaces the repeats (they are hidden while it runs) and `weapon_chain_sim` off brings them back, the A/B.
12. **`weapon_landed` is announced at the first `body_entered` after a throw or a drop, once; a thrown weapon that breaks announces `weapon_broke` only.** / Not on every touch, and not also on a break. / The director plays `weapon_land` where it fell; a bouncing pipe must not clatter five times, and a breaking weapon has its own sound.
13. **The training room holds the bike chain beside the pipe** (`TestRoom.chain_position`, two metres from it, after the pipe in tree order so the tests' `get_first_node_in_group` still finds the pipe). / Not a separate room. / Game-boy can pick up each weapon in the room he already tests in.
14. **The Thug's `pipe_color` and `pipe_radius` exports are removed**, with the test line that asserted the colour (`test_pipe_thug.gd`: "nor is the pipe a red" on `pipe_color`, replaced by "the carried pipe scene has art"). / Not leaving dead exports. / The art is one painted pipe (PROPS), and the colour assertion's purpose, no red pipe (SPEC section 10), now holds by the art's palette (`pipe_paint` has no red: `test_static_art.gd`).
15. **`cheat_menu.gd`'s `dummy.color = spawn_colors[...]` line is dropped** (the lead's note: the dummy wears art now). The `spawn_colors` export stays, unused. / Not removing the export: a saved scene may set it.
