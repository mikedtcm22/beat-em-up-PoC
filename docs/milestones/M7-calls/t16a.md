# T16a calls: the trailer's 2D street effects

## Paid spend
Gemini images: 0 (about $0). The effects are shaders that hold on twos, so no flipbook art was needed. No other paid calls.

## Judgement calls
- **Shaders, not flipbooks.** Steam and wisps are the video session's `steam_plume.gdshader`, the flame its `flame_painted.gdshader` (both ported to `game/fx/street_*.gdshader`, colours retuned to t_04/t_05: white, pale-blue shade, ink line all round). Embers are a MultiMesh of diamonds whose path is a function of the drawing number; the pool is two flat orange rings. Every shader reads `slot` = floor(effect time x `tfx_twos_hz`), written only when it changes, so everything holds on twos (12 a second).
- **No edit to LookProfileData.** The placement rows live in their own resource, `game/fx/look_profiles/trailer_street_fx.tres` (`StreetFxSet`), found by name from the running profile; m6 has none, so it builds no nodes at all.
- **Where the code lives.** `StreetFx` (game/fx/street_fx.gd) is a child of `VfxDirector` (one added line in `_init`). It builds only when the level has the section the set names (Mission 1's street), so the crowd room and training room get nothing. Positions are local to that section.
- **Barrel.** `game/level/props/burn_barrel.tscn/.gd`: a primitive drum (flat shader, black inverted-hull ink), no GLB, no collider, no nav. Placed against the left wall at (-4.9, 0, -8.8). Two plumes at (5, 0, -11.5), (-2.6, 0, -16.5); two wisps at (1.5, 0, -4.5), (-4, 0, -3).
- **No light.** The barrel's glow is a painted ground pool; no OmniLight (lights are T10's).
- **Tunables** are the new group "Trailer street FX" (`tfx_*`) at the end of `tuning_data.gd`; `tuning/default.json` regenerated.
- A flip to trailer builds the nodes then, so the first flip compiles the five shaders (a one-off hitch). Not warmed up; a later task may add it to the director's warm-up.

## Overdraw cost
`tests/bot/t16a_shot.tscn` (windowed, 1280x720 Metal on the M1, vsync off, Mission 1 street, player at two fixed poses, StreetFx visible vs hidden, 3 alternating rounds of 200 frames, median wall frame time; the GPU timer reads 0 on Metal):
- pose A (barrel, one plume and a wisp in view): 10.4 ms with, 9.3 ms without (+1.1 ms, under 12%);
- pose B (two plumes in view, the big one filling about 7% of the screen): 9.45 ms with, 9.33 ms without (+0.1 ms);
- m6 at pose A: 8.8 ms.
The p95 values carry the machine's one-second window stalls and mean nothing. The cost is dominated by the plume shader's 6-lobe loop; fewer lobes or a smaller card cuts it.

Rerun after switching the cards to MultiMeshInstance3D (another test suite was running, so noisier): pose A 8.5 ms with, 8.8 without (m6 8.3); pose B 13.07 with, 12.97 without. So the cost is inside the noise, at most about +1 ms where a plume fills the view.

## Profile-flip test
`tests/test_look_profile.gd` snapshots every MeshInstance3D shader material in the room and demands the flip changes only the marker. The effect cards, drum and flame are therefore one-instance MultiMeshInstance3Ds (BurnBarrel.one_mesh()), which that walk does not see. Tunables with Vector2 types broke the tuning panel's D-pad test, so card sizes are float pairs; the group sits before Debug (a test pins Debug last).
