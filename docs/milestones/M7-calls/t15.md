## Judgement calls
- **Gemini was unavailable, so every tile is painted by `tools/gen_trailer_kit.py`** (Pillow, hand-written shapes with tapered ink, flat tones, fixed seeds). The brief's route was Gemini tiles assembled by the generator; the generator's layout (rows, U/V metres, strip table, ink alpha, wrap-drawing) is the part that carries over, but a Gemini tile would need an import step (crop, make seamless, derive the ink mask) that is not written, because nothing could test it. Follow-up when credit returns: run jobs.json, add a loader for `assets/source/trailer_kit/<tile>.png` ahead of the procedural painter.
- **Same strip names and rows as M6**, so `KitMesh` indices (vertex-colour alpha) are one thing under both profiles. The sheet's rows differ in height (brick 576 px for 3 m, glass 384, facade 320) because the shader reads `v0`, `vh` and `period_m` from the table and `ROWS` stays 16.
- **U scale per strip** (`u_m`) lives in the strip table and `KitMesh` multiplies a face's U by `Tuning.kit_trim_m_per_tile / u_m` under the trailer profile. This needed no shader change.
- **Variants are baked into meshes** (UV offset, mirror, tint) because per-instance shader data is not available; a flip swaps each block's mesh in place. Variant count 12 by default, tunable (`trailer_kit_variants`).
- **Sheet swap without touching `toon_materials.gd`:** `TrimSheet.apply_profile()` sets `trim_tex`, `ground_tex` and `strips` on `ToonMaterials.trim()` and `trim_scissor()` after a flip (it does not set any uniform `apply_look` sets).
- Edits outside "kit art" files, all additive with defaults: `RoomKit.box_mesh` gained a `variant` parameter (default -1); `LevelBlock`, `InsetBlock` and `KitPiece` pass a variant and listen to a profile flip.
