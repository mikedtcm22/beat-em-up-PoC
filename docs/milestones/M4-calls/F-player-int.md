# M4 calls: F-player-int

Package F-player-int (phase 2, M4-plan A14): the player wears `CharacterArt` through `CombatActor.art` like the Punk, starting on the probe body because the hero has not been picked (F-player-art has not run, so `assets/export/characters/player/player.glb` does not exist). It also holds the slice gate's gap 7 (F-player-int's line: the lens rules on the player's skinned art) and feel question 3 of M4-plan section 8 (`fp_knockdown_hide_torso`, in the camera file). Each call is the decision, an alternative not taken, and why. Every figure is printed by `tests/test_art_player.gd` as an `ART-PLAYER ...` line. The machine was shared (load average 3 to 5); the share, count and distance figures are exact, the wall-clock ones are not used.

## 1. The wiring

**C1. The hero's GLB is named in the art resource's metadata, so a missing file is a silent no-op.**
- *Decision.* `game/actors/art/player_art.tres` is a `CharacterArt` with `id = &"player"`, the shared atlas, `triangle_budget = 30000`, no `scene` and two metadata entries, `scene_path` (`res://assets/export/characters/player/player.glb`) and `detail_mask_path` (`.../player_detail.png`). `player.tscn` carries it as `art`. `PlayerCharacter._configure_art()` asks `PlayerCharacter.worn_art(art, Tuning.data.look_player_art_probe)`: the probe art when the switch is on; else the scene's art as it is when it carries a scene; else a copy of it holding the GLB (and the detail mask when that file exists too) when `ResourceLoader.exists(scene_path)`; else **null**. Null is the M3 build: `HumanoidRig.art == null` builds the 45 primitives, no proxies, no art meshes, no warning and no resource error (tested). One copy per art is kept (`_hero_art`), so `SkinnedArt`'s cache (keyed by the art's instance) holds. F-player-art's GLB, put at that path, makes the player wear it with no edit to any file.
- *Alternative.* An `ext_resource` of the GLB in `player_art.tres` (the way `punk_art.tres` does it); or `ResourceLoader.exists()` in `player.gd` around a `load()` of a second resource.
- *Why not.* A `.tres` whose `ext_resource` file is missing fails to load with an `ERROR` that no guard can precede (the whole resource fails, so even the palette goes), which the brief rules out in the game, the tests and the recordings. A second resource per state would make "the GLB appears" an edit instead of an event.
- *Not a spec departure.* A scene's `art` is still `CombatActor.art`; the metadata is only where the file's name lives until it exists.

**C2. The probe is behind a Debug switch and applies to every `PlayerCharacter`.**
- *Decision.* `look_player_art_probe` (bool, false, Debug group: presets skip it, so the shipped game never wears the probe; `tuning/default.json` regenerated, unchanged). It is read when the body is built, like `look_punk_art_variant`. `game/actors/art/player_probe_art.tres` is a `CharacterArt` of `tests/fixtures/art/probe_body.glb` (`id = &"player_probe"`, 30000 triangles). The switch also applies to a `PlayerCharacter.new()` with no scene, which is what lets the suite run with the player in the probe (C4).
- *Alternative.* Build the probe's `CharacterArt` in code in `player.gd`; or make the switch live (`Tuning.changed` swapping the art like `look_show_art`).
- *Why not.* A `.tres` next to `punk_rest_art.tres` is the project's own way (and is one more file in my own `player_*` namespace). A live swap would have to rebuild the player's rig: `HumanoidRig._build_meshes()` connects `Tuning.changed` once per build, so a second `build()` with art connects twice and errors. The acts say how to record with the probe on (C9).
- *A game file naming a test fixture.* Only the Debug-gated resource does; with the switch off nothing loads it.

**C3. The art's hull is the first-person one, asked for by its key (a request stands).**
- *Found.* `RigPaint.outline_material()` returns `ToonMaterials.outline()`, which is `_hull(Hull.ART, false)`: the full-width character hull for every art, so a player wearing art would draw his arms at `look_outline_px`, not the bible's x `look_outline_fp_scale` (0.8; M4-look-bible, J14 "outlines aren't heavy"). The primitives get the variant (`outline_for_part(shape, first_person)`); the art has no flag.
- *Decision.* After the rig is built `PlayerCharacter._wear_first_person_hull()` gives each art mesh `ToonMaterials._hull(ToonMaterials.Hull.ART, true)`: the shared, tracked material of the same shader with `fp_scale` and the lens fade, which `ToonMaterials.apply_look()` keeps current on every `look_*` change (tested live: `look_outline_fp_scale` 0.5 and `look_outline_px` 5 reach it). It calls a private-by-name static of another class: one line, loud if it is ever renamed (a parse error).
- *Alternative.* Make the two-line change where it belongs (`ToonMaterials.outline(first_person := false)` and `RigPaint.outline_material()` passing `_rig.first_person_body`); or duplicate the hull material in `player.gd` and re-implement `apply_look` for it.
- *Why not.* Those files are P1-toon's and F-look's (A14 gives me `player.*`, the art `.tres`, the camera and my tests); the rule is to ask, not to edit. Duplicating `apply_look` would leave two copies of the Look values' routing. **Request:** do the two-line change and delete `_wear_first_person_hull()` (its test, `test_the_art_hull_of_the_players_body_is_the_first_person_one`, reads the overlay, so it passes before and after).

## 2. What the suite shows with the player in the probe

**C4. The seven fallout files need no edit; twins are added where the suite measured the player through the proxies.**
- *What was run.* With `look_player_art_probe` defaulting to true (temporarily), the whole suite: 70 scripts, 1503 tests, **1502 passed**; the one failure was my own assertion that the switch defaults to off. That covers `test_grab_view`, `test_ko_view`, `test_player_grabbed`, `test_launch_from_hold`, `test_health_bars`, `test_humanoid_rig` and `test_hit_flash` with every `PlayerCharacter` (the test room's, the bare ones) wearing the probe, so they pass unedited with it on (A4: they measure the proxies, which follow the same skeleton) and, since the default is off, with the primitives. The default was put back to false.
- *So no old -> new to log.* No assertion in those files was changed or weakened. The brief's rule asks for a twin on the visible path where the old one measures proxies, and those are:
  - **hold** (`test_grab_view`'s lens rules): `test_a_hold_keeps_the_skinned_forearms_and_hands_off_the_lens_and_the_own_body_to_a_third` (C7);
  - **the KO view** (`test_ko_view`'s head-layer and own-body rules): `test_the_ko_view_keeps_its_distance_from_the_skinned_body_and_shows_all_of_it` (C7);
  - **held by an enemy** (`test_player_grabbed`'s "his own body a third at most"): `test_the_held_view_on_the_skinned_art_keeps_the_own_body_to_a_third_and_off_the_lens`, added to `test_player_grabbed.gd` (the only existing test file edited, by one `preload` and one test): 12 samples, the own body 0% of the view, nearest drawn vertex 0.261 m against the 0.25 m bar;
  - **the knockdown view** (the belly slab, nobody measured it on art): C8.
  - `test_launch_from_hold` (the victim's lens distances), `test_health_bars` (enemies' heads) and `test_hit_flash` (the flash's anchor and frames, which `test_skinned_art` and `test_art_punk` repeat on art) do not measure the player's own drawn body.
- *Alternative.* Parametrise all seven files over "primitives and probe" (each setup run twice).
- *Why not.* Doubles about 90 s of suite time for tests that passed unedited with the probe on; the twins above are the cases whose measured thing changes (what the lens draws).

**C5. A9 on the probe is a ratchet, on the hero it is the plan's bar.**
- *Measured (the probe, 15 poses of `test_humanoid_rig` and `test_skinned_art`: idle ahead, down 45 and 60, jab, cross, hook, uppercut, block, block down 20, the knee in the hold, the front kick down 20, the spin kick at view 0, 120 and 240, the haymaker's charge).* Against FPView's proxies: cells that differ at most 5.2% (the block; the knee 3.1, the front kick 3.0, the jab 2.8, all others under 2.2), the share of the view within 5.3 points (the block: art 19.4%, proxies 24.7%), the art nearer than the proxies by 3.1-3.6 cm in the four punches and 5.8 cm in the kick (FPView is looser than the primitives as drawn, P1-skin C6, and against the proxies' own meshes the punches are 0.2-1.5 cm and the kick 2.5 cm), and by 39 cm in "down 60" (two cells on the view's bottom row, where the art's thigh edge is in front of a toe cap that the proxies' ray passed beside: a silhouette, not a bulge; the distance is not the thigh's). The proxies' cells covered by the art: 63% in the knee (the hold's low framing), 72% in the front kick, 74% looking down 45, 79-80% in the block and down 60, 85-100% elsewhere.
- *Decision.* The probe is a mannequin whose proportions are a voxel remesh's, so against the plan's 3%, 4 points and 2 cm it misses in nine poses (marked `GATE` in the print). It is held to what it does today, so a change that makes it worse fails: cells that differ at most 6%, share within 6 points, never 7 cm nearer than FPView's proxies nor 3 cm nearer than the proxies' own meshes (but at "down 60"'s two silhouette cells), covering at least 60% of the proxies' cells where they fill 3% of the view. **The hero's art, when it exists, is asserted against the plan's row A9 exactly** (3%, 4 points, 2 cm, against FPView's proxies): if it misses, the test names the pose, and the gate decides with the exact-proxy figures beside it (P1-skin C6).
- *Alternative.* Assert the plan's bars on the probe (nine red poses), or assert nothing on it.
- *Why not.* The first would make the suite red for a body that is not the product (P1-skin C8 did the same for the strain run); the second would let a regression in the pipeline's probe or in the proxies pass. A teeth test (`test_the_framing_check_has_teeth_an_art_with_a_bulge_fails_it`: the body swollen 15 cm along its normals) fails the check, so the figures can fail.

**C6. Watertight: no open edge on Body, the seam closes, non-manifold edges printed.**
- *Measured.* The probe's `Body` has 0 open edges (every cut capped). `Body__fp_hidden` has 174 (its cuts at the waist and the arms), and every one is an edge of `Body` (the seam closes: the two meshes together are closed, so the KO view shows no hollow where it shows both). `Body` also has 23 edges shared by three or more triangles (non-manifold; where the caps meet). Asserted: no open edge on `Body`, the hidden part open where it was cut, every open edge of it on `Body`. Printed, not asserted: the non-manifold count (the probe has some; a hero with none would pass a stricter bar, but it is not the plan's).
- *Alternative.* Assert no non-manifold edge.
- *Why not.* The probe fails it; the plan's words are "watertight, caps closed", which the first three asserts are.
- *Seen.* In the KO view the seam is a thin line across the probe's torso (where `ArtBody`'s hull meets the hidden mesh's cut): see part 4.

## 3. The lens rules on the skinned art (gate gap 7), and feel question 3

**C7. Hold and KO view on the drawn art (`SkinnedView`, the drawn pose).**
- *Hold* (grab, three knees, a regrab, the throw, in the test room, the real `FirstPersonCamera.view_from_eye()`; 113 samples): the nearest forearm or hand vertex to the lens **0.320 m** (the rule: 0.3 m, `test_grab_view`) and the own body **25.1%** of the view at most (the rule: a third). Both pass with the probe; the margin on the forearm is 2 cm.
- *KO view* (the killing blow, the lens out, held, the get-up, back in; 65 samples; the proxies' own figures are `test_ko_view`'s): with the head layer lifted the nearest vertex of the drawn body (both meshes) to the lens **0.344 m** (the rule: 0.25 m, which is `ko_view_clearance_m`, the figure `FirstPersonCamera._head_clear_of()` tests the proxies against), the own body at most **17.3%** of the view, and the head layer pops **0.0%** of the view on the lift and on the hide (the bars: 8% and 2%). The layer is lifted once and hidden once, the rig's layers are as they were after the get-up, and the whole body shows while the lens is out.
- *Alternative.* Cast the primitives' proxies (FPView) as the existing tests do, or sample every tick.
- *Why not.* Those are the existing tests (still green) and measure what nobody sees; the art's cost is 10 ms a sample, so the hold samples every other tick and the KO view every third (headless suite time 10 s for the file).
- *The camera's check reads the proxies.* The probe's art is not nearer the lens than the proxy boxes' clearance in this case (0.344 against 0.25 m); a fitted hero whose head is bigger than the proxy's boxes would show it here, which is why the test also asserts the camera's own `ko_view_clearance_m` against the art.

**C8. Feel question 3: `fp_knockdown_hide_torso`.**
- *Measured, off (today).* A knocked-down player (not KO'd) lies face down and the lens sits in his own belly. The Kicker's sweep from behind in the test room (the primitives): the own body covers **74%** of the view at most, over a third for 76 frames and over half for 45 of the 121 frames of the knockdown (LAUNCHED, DOWNED, GETUP); the parts are `BellyTop` (844 of the sampled cells) and `Belly`. In the crowd room (the act `Look: my knockdown`, the Kicker ahead) the same slab reads 59, 49, 49, 51, 52, 52% down and **83%** at the first frame of the get-up. With the probe body the slab is 37% at most (the probe's belly is round where the primitives' is a box and a cylinder): over a third for 6 frames. In the test room only the sweep from behind shows it (the front, the left and behind-left read 0%, and the Bruiser's smash from the front and from behind-left too); in the crowd room the sweep from ahead and from either side shows it and from behind and behind-right does not. The bearing that fills the view differs by room (open risk d); the act uses the one that does in the crowd room.
- *Decision.* `FirstPersonCamera._update_torso()`, each `update_camera()`: when `fp_knockdown_hide_torso` is on, this camera is current, and the player is alive and in LAUNCHED, DOWNED or GETUP with the lens in his eyes (`_ko_view` is 0: the KO view shows the whole body, and a KO's get-up keeps it), the torso meshes move to `VIS_FP_HIDDEN`, the layer this lens never draws (they still cast shadows; every other camera has the default mask), and back to the layers they had when the knockdown ends, the player dies (the KO view takes the lens), the camera stops being current, or the switch goes off. The torso is the primitives on the Hips and Spine bones (Pelvis, Belt, Belly, BellyTop: the chest and above are on the layer already) and, when the player wears art, the art's visible body (`ArtBody`). It is re-applied every update while it holds, so a rig that resets its layers meanwhile is hidden again. The default is false, which touches nothing: the layers never change, so every existing test and every first-person number is today's.
- *Measured, on.* The primitives: **15%** of the view at most (what is left of the body: the knees come up), **0 frames** over a third (was 76), torso hidden on all 121 frames. The probe: **0%**, 0 frames over a third (was 6).
- *The art's torso is its whole visible body.* `Body` has no part of its own for the belly (the GLB's one split is `Body__fp_hidden`, chest and above), so on the art the switch hides `Body` as a whole: the legs and forearms with it, which the primitives case keeps (the two knees in the on-sheet below). In the knockdowns measured the slab is all there is of the own body in view, so the practical difference is the knees. **Request (F-player-art, if Game-boy wants the switch):** a third mesh, `Body__fp_torso` (Spine and Hips, the belly and belt), which `_find_torso_meshes()` would take with a one-line change; until then the art version hides more than the primitives'.
- *Alternative.* A new visual layer for the torso (`CombatTypes.VIS_FP_TORSO`) and a cull-mask bit on this lens, so no mesh's layers ever change; hiding it in DOWNED only, or by the lens's own height; or the torso's `visible = false` (which would also hide it in the side view).
- *Why not.* `combat_types.gd` and `humanoid_rig.gd` are not mine, and a layer assigned at build would change layers in every test of the rig; the camera moving layers only while the switch is on and the knockdown is shown leaves everything else bit-identical. The slab is only in DOWNED and the get-up's first frames, but LAUNCHED costs nothing (0% there) and the states are one predicate; `visible` breaks the side view and free fly.
- *The judgement (his).* On: the lying view is the street and the Kicker's legs, clear; the body is not there at all, and that is the price. Off: a belly across the view for a second or two, then a pop to the get-up. Left at today's, as asked.

**C10. What the sheets show (read first person, `look_sheets.sh` stills and 6 fps overviews, 1600x900; the probe is a mannequin, not the hero).**
- *The wiring reads right.* At 45 and 65 degrees down the lens sees the probe's legs, trousers and dark shoes, with a thin continuous ink line (the player's x0.8 hull, about 2 px in the 1600x900 stills at 0.3-0.6 m, read by eye, not measured with the probe; no heavy line, none on the lens) and the toon bands, and on the street the shadow of the whole body, the hidden chest and head included (the split casts it). No view shows the inside of the head or chest, and no pop at the split in the frames read (the strikes, the guard, the spin kick, the hold and the KO's lift; the tests measure the head layer's pop at the KO's lift and hide at 0.0%).
- *Strikes and the guard.* The forearm comes in as a blue sleeve with a dark cuff and a lilac wrap highlight at the wrist; in the guard the two forearms and cuffs fill the top corners and stay clear of the lens (0.3 m). ## 5. Interfaces, tunables, requests, risks

- *Interfaces.* `PlayerCharacter.worn_art(scene_art: CharacterArt, probe := false) -> CharacterArt` (static), `PlayerCharacter._configure_art(r)` (override), `PlayerCharacter.PROBE_ART_PATH`, `ART_SCENE_META`, `ART_DETAIL_META`; `FirstPersonCamera.TORSO_BONES` and the knockdown view's behaviour (`_update_torso()`, `_knockdown_view()`, `_find_torso_meshes()`, `_restore_torso()`, private); `CharacterArt` resources `player_art.tres` and `player_probe_art.tres`.
- *Tunables.* `look_player_art_probe` (Debug, false), added; `fp_knockdown_hide_torso` (Look > FP feel, false) was S0's seed and is now wired.
- *Requests.* (1) P1-toon/F-look: `ToonMaterials.outline(first_person := false)` and `RigPaint.outline_material()` passing `_rig.first_person_body`; then delete `PlayerCharacter._wear_first_person_hull()` (C3). (2) F-player-art: the GLB at the path in C1 (`Body`, `Body__fp_hidden`, optional `player_detail.png`); if feel question 3 is wanted on the art without hiding the legs, a `Body__fp_torso` mesh (C8). (3) The lead, when the hero's GLB lands: add it to `test_skinned_art`'s strain run (A19, "F-punk and F-player-int add their GLBs to it"); `test_art_player` already runs A9, the watertight check, the hold, the KO view and the knockdown on it. (4) The lead: ARCHITECTURE's P3-early heading still says `fp_knockdown_hide_torso` is "P3-int proper's to wire": it is wired here.
- *Open risks.* (a) The probe's A9 figures are not the hero's: the hero's art is asserted at the plan's 3%, 4 points and 2 cm against FPView's proxies, which are looser than the primitives as drawn (the probe's punches read 3-4 cm "nearer" against FPView and under 2 cm against the proxies' meshes), so the first hero GLB may fail on FPView's looseness, and the gate then decides with the exact-proxy figures. (b) The hold's forearm margin is 2 cm on the probe (0.320 against 0.3 m). (c) `_wear_first_person_hull()` calls a private-by-name static. (d) Face-down knockdown looks depend on the room (the test room's slab is from the sweep behind, the crowd room's from ahead; I did not find why). (e) With the hero's GLB the player in the test room wears it by default (no switch), and the suite then runs every player test on it: only the 1502/1503 figure of C4 says how the suite does with the probe.
